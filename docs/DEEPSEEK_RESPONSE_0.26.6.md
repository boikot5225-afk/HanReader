# DeepSeek: отклонение ответа — 0.26.6

На телефоне в 0.26.5 ручное уточнение неизвестного прозвища `Mataamigos` показало
«Некорректный ответ DeepSeek. Переводы не сохранены». Исходный ответ телефона недоступен:
по одному скриншоту нельзя установить, какое именно поле не прошло проверку.
Реальный запрос с пользовательским ключом в рабочей среде не выполнялся.

В коде обнаружены и воспроизведены несколько причин отказа:

- Для неизвестного слова `current_translation: null` отклонялось вместо пустой строки.
- Пустое пояснение или неиспользуемое предложение `""` вместо `null` отклоняло весь пакет.
- `span: null` для отдельного слова приводило к ошибке разбора.
- Правильный текст выражения отклонялся из-за ошибочно подсчитанных моделью числовых
  позиций. Подсчёт UTF-16 особенно ненадёжен при эмодзи и длинных абзацах.

## Изменения

Отсутствующее исходное значение допускает пустую строку или JSON null. Для существующего
перевода по-прежнему требуется точное совпадение. Пустые необязательные строки означают
отсутствие пояснения/предложения; пустое исправление с `needs_correction=true` запрещено.
Переносы и табуляция внутри коротких строк нормализуются в пробелы. Прочие управляющие
символы, превышение лимитов и неверные типы отвергаются.

Для выражения модель возвращает точную непрерывную цитату `span.text`. Приложение само
находит её в исходном абзаце: диапазон обязан включать запрошенное употребление, совпадать
с границами полных токенов, иметь длину до 180 символов и не затрагивать ручные значения.
Неоднозначные повторения отвергаются. Прежние числовые позиции могут разрешить
неоднозначность только при точном совпадении с реальным диапазоном; приложение не доверяет
им для изменения текста. Слово без span остаётся на позиции из запроса.

Запрос одного неизвестного слова содержит небольшой `response_template` с его настоящими
ID, исходным написанием и пустым значением. Обычные пакетные запросы его не дублируют.
Шаблон и уточнённая системная инструкция уменьшают вероятность ответа по общему примеру.

Отказ теперь содержит фиксированную причину и код: FORMAT, TERMS, SOURCE, VALUE, SPAN,
PROTECTED или CONFLICT. Код и текст не содержат API-ключа, фрагмента книги, ответа провайдера
или сообщения внутреннего JSON-парсера. При новом запросе прежняя ошибка сбрасывается.

## Сохранённые гарантии

Неверный/обрезанный JSON, посторонние или повторные ID, изменённое исходное слово,
выдуманная цитата, противоречащие пересечения и пустые исправления не попадают в БД.
Пакет проверяется целиком до записи. Автоматических платных повторов нет.
Главный словарь, приоритет ручных значений, кеш уже оплаченных проверок и его ключи
не менялись. Room 15 и архив 5 остаются прежними. Серверная озвучка отключена.

## Проверки и границы результата

Новые мокированные сценарии находятся в `AiResponseTest`: прозвище с null/пустыми полями,
ошибочные позиции после эмодзи, выражение по точной цитате, пересекающиеся повторения,
защита ручных значений, нормализация пробелов, отказ опасным/несогласованным ответам,
сохранение на диск и повторное использование после открытия БД без API-запроса.

Совместимость с прежними конструкциями, тремя языками и полным экраном читалки проверяют
ContextAiTest, AiLanguagesTest, AiReaderUiTest и AiUiTest. Те же проверки формата добавлены
в production-прогон CI. Первые 45 целевых проверок прошли, затем 27 проверок ядра прошли
после финальных изменений. Полный CI run 44101620505 завершился успешно; release/debug
APK 0.26.6 (code74) скачаны, проверены и переданы владельцу. Подписи сохранены, серверная
озвучка отсутствует. Размеры и SHA-256 записаны в HANDOFF. Это не проверка качества
реального ответа модели и не подтверждение точной причины ответа с пользовательского телефона.
