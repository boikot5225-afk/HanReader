# Контекстный аудит испанского модуля: 0.24.8 → подготовка 0.24.9

Дата: 14 ноября 2026. Ветка `amauta`. Исходный коммит `d6eca59` (0.24.8, code 61).

## Что именно измерено

310 настоящих контекстов: **250 El narco + 60 El guardagujas**. Это целевая диагностическая выборка сложной лексики, а не случайная выборка всех слов книг. Все доли ниже относятся только к ней. В выборке 178 различных написаний и 147 эталонных лемм/наборов допустимых лемм. Повторные употребления одного слова не являются независимыми языковыми единицами.

Разметка создана моделью **до просмотра предсказаний**, независимо от ответов приложения. Это предварительный эталон, не экспертная верификация 310 переводов. Сопоставление — по вручную заданным семействам русских синонимов (regex), а не буквальному совпадению строк. Возможны неполные перечни синонимов и ошибки разметки. Поэтому приведённые числа — воспроизводимые результаты этой разметки, не доказанная точность испанского языка вообще.

Эталон неизменён: SHA-256 `1591eeaa088751e6194300a348dae61cef73c79d911e528ea85cf01dc0797aab`. Из явных спорных разметок два переносных `cayeron` заранее помечены review; ещё семь записей с неточным эталоном леммы/конструкции явно переведены оценщиком в UNRESOLVED одинаково для обеих версий. Они не исправлены на «успех» и остаются в знаменателях. Список ID открыт в `score.py`; отложенный JSONL не переписан.

200 контекстов El narco использованы для диагностики. 50 отложенных выбраны до правок по SHA-256 ID; результаты не использовались для подбора исправлений. Разделение по употреблениям, не по леммам: слова могут совпадать между частями. El guardagujas — контроль этой итерации; прежние версии уже доводились на этом рассказе, поэтому он не является ранее неизвестным корпусом для проекта.

Проверка выполнялась с исходным текстом каждого абзаца приложения, штатным `EsEngine.chapter → cardAnalyses → senses`, штатными `glossShort`, `cardTranslation`, `phraseAt/phraseKey`. Путь совпадает с WordSheet для нового профиля без своих переводов, с вариантом ANY. JVM-запуск заменяет Android-хост, а не языковой движок, EPUB-парсер или словари. Интерактивное поведение Compose на устройстве этим запуском не проверяется.

## Архитектура: фактический путь перевода

1. `EpubBook`: ZIP → container.xml → OPF manifest/spine → NCX/nav; порядок задаёт spine. Jsoup + BlockWalker сохраняют текст inline-узлов внутри абзаца, заголовки, сноски и стили. Извлечение аудита использует именно этот класс. Оглавление и библиография исключены метаданными аудита, не языковыми правилами.
2. `ChapterBuilder` передаёт абзацы в `LanguageModule.chapter`; испанский готовит каждый абзац через `tokenize → inContext`. Токены имеют исходные смещения. Буквы, внутренние дефисы/апострофы образуют слово; числа и пунктуация отдельны. Акценты не удаляются при обычном поиске статьи; снятие ударений используется в поиске по книге и разборе присоединённых местоимений. Добавлена NFC-нормализация ключей и поддержка комбинируемых акцентов без изменения смещений текста.
3. `dict.tsv` + `forms.tsv` + `grammar.tsv`: таблица словоформ, альтернативные части речи, специальные частотные приоритеты, снятие присоединённых местоимений. Это словарная морфология с эвристиками, не полноценный синтаксический анализатор.
4. Источники — русский и английский Викисловарь/kaikki, ранее подготовленные машинные русские значения, ручные правки `data/es/manual.tsv`. Русская статья собирается заранее, при клике источники не опрашиваются по сети. Приоритет: контекстно выбранный смысл, затем порядок словаря с настройкой региона; русские значения предпочитаются английским. Код источника сохранён в трассе (`w/a/r/h`), `machine` не означает сетевой вызов сейчас. Существующая UI-подпись ручной статьи может говорить «Викисловарь» — поле трассы точнее этой подписи.
5. `inContext`: местоимения, артикли, вспомогательные глаголы и некоторые конструкции помогают выбрать лемму/часть речи. `ContextRules` уже существовал: `near`, `before`, `after`, `next`, `after-verb`; новый слой с нуля не создавался. Добавлены ограниченное окно `within` и предыдущее слово `prev`, возврат леммы правила, строгая проверка неизвестных условий.
6. Общего алгоритма разрешения любого словарного значения нет. Без подходящего правила показывается статический список. Только 62/310 проверенных употреблений получили пометку выбранного правила после правок (до: 5/310); остальные успешные первые значения не доказывают контекстного понимания.
7. Выражения: самый длинный подходящий словарный диапазон, канонизация первого слова/возвратного глагола, сжатые предлоги `del/al`, фильтры ложных сочетаний. Теперь проверяются до шести слов, горизонтальные пробелы нормализуются, полная словоформа выражения может вести в каноническую статью. Ограниченная длина и неполная морфология внутренних слов остаются.
8. `WordSheet` по нажатию получает `cardAnalyses`, показывает `senses`, альтернативные разборы, английские значения и панель выражения с кнопкой «Выделить». Пользовательское значение места/книги/языка может переопределить словарь; эти переопределения в аудите выключены. `cardTranslation` — сохранённый перевод, не обязательно прежний видимый список; именно это расхождение устранено для контекстных правил.
9. Кеш: синхронизированный LRU до 20 000 разборов ключуется нормализованным словом. Он кеширует только словарную морфологию, не выбранный контекстный смысл. Контекст вычисляется на каждом подготовленном абзаце и хранится в токене. Статьи для карточки копируются, кеш не мутируется. A→B→A на одном движке проверяется тестом. Словари mmap-кешируются по времени обновления APK, загрузка разделена по языкам. Кеш UI был отдельной слабостью и исправлен.
10. Облачного ИИ в этом пути нет. Есть офлайновые подготовительные скрипты машинного перевода и отдельный сетевой TTS; это не контекстный перевод при чтении. Сетевых запросов на кликах: 0; доля обращений к облаку: 0/310. Сравнение качества/задержки с несуществующей AI-конфигурацией не имитировалось.

## Подготовка и сохранность данных

Оригинальные EPUB не копировались в Git, CI или внешние сервисы. Локальный парсер извлёк 1561 содержательный блок / 7585 предложений El narco и 60 содержательных блоков / 175 предложений El guardagujas. Эти числа — по эвристике границ предложений, не ручная разметка всей книги. Для корпуса отдельно соединяются продолжения прозы после разрывов издательской страницы, сохраняются исходные диапазоны блоков. В контрольном EPUB исключены метаданные, «Página …», FIN, словарная сноска издателя и реклама сайта. При этом испытания движка получают исходный абзац, как читатель, а не улучшенный текст корпуса: отсутствие межабзацного контекста не маскируется.

JSONL содержит ID книги/главы, архивный путь, блок и смещения, написание, эталонную лемму, предварительную часть речи, ожидаемый смысл, альтернативы, нежелательные значения, объяснение, уверенность и происхождение. Некоторые POS помечены широким классом и требуют ручного уточнения; это не корпус с экспертно размеченной морфологией.

В `.work/context-audit` сохранены замороженный эталон, исходные/повторные трассы, метрики, короткие примеры ошибок и локальные инструменты разметки. Всё исключено из Git. Публичные тесты используют только оригинальные синтетические предложения. Для переноса приватной проверки предусмотрен архив результатов без EPUB, полного извлечённого корпуса, SDK и кешей.

## Остаточные ограничения

Сохранились ошибки в отдельных `cuota`, `piso`, `capital`; часть зависит от предыдущего предложения либо далёкого грамматического признака. Контроль сохранил ошибки `cuerpo`, `redoble` и спорные/неточные значения. Имеется нераспознанное полное сочетание `operaciones comerciales`; обычный перевод его частей — отдельный путь от выбора всего диапазона. В 9 записях эталон/лемма не позволяют уверенную оценку. Даже строгий парсер правил не превращает эвристические признаки в полноценную семантическую модель: перенос на другие тексты требует дальнейшей независимой проверки.

Android-эмуляторы и реальный телефон в этом аудите не использовались. Не проверена интерактивная смена карточек на устройстве. Выпуск в магазин, облачные переводы и новые сетевые API не выполнялись.
